# Splice 前缀缓存实测报告

实验时间：2026-10-23 UTC；整理与复核：2026-10-24。模型为真实本地 Qwen3-1.7B，业务数据为仓库虚构数据，新增云端调用为 **0**。

**前缀 KV 缓存值得实施。** 在相同模型、线程和输入下，两条完整意图输出的生成耗时分别从 **80.16 秒降到 35.85 秒**、从 **76.36 秒降到 36.19 秒**，缩短 **55.3% / 52.6%**。缓存前后输出逐 token 一致，预算与权限检查结果一致。

收益主要来自跳过重复输入的神经网络计算。首次建缓存仍用了 **48.87 秒**；命中后，逐 token 生成还占约 **34 秒**。因此缓存解决了一大段阻塞，但本次环境下仍不能达到几秒钟完成整个请求。

本次交付是独立实验代码与证据，**尚未给生产 CLI 接入缓存**。当前 CLI 每次启动独立进程；要获得跨请求命中收益，需要在 Agent 的长期存活进程中保留模型和缓存。这可以作为端侧推理模块实现，符合项目省去专用中间业务 Service 的架构方向。

## 实验如何控制变量

| 条件 | 本次设置 |
| --- | --- |
| 模型 | Qwen/Qwen3-1.7B |
| 模型与 tokenizer revision | `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e` |
| 后端 | PyTorch 2.14.1+cpu / Transformers 4.57.6 / SDPA |
| 精度与线程 | CPU BF16，计算线程 2，interop 线程 1 |
| 容器资源 | CPU 时间配额约 2 核，内存上限 8 GiB |
| 输入 | 每次 1,844 tokens；公共前缀 1,781，当前请求后缀 63 |
| 缓存范围 | 固定指令、能力目录、选中的教学资料及例句；占输入约 96.6% |
| 解码 | 贪心、`do_sample=False`；两组均启用请求内 KV |
| A 组 | 模型已驻留，每次重算整个 prompt，不跨请求复用前缀 |
| B 组 | 同一个模型，命中前缀缓存，复制 KV 后只计算新后缀 |

先做短预热，单独测量缓存构建。随后以 AB / BA / AB / BA 顺序，测试保留 15、20、50、16 元四个输入，每次固定生成 16 tokens。最后对 15、20 元请求各测一对完整输出，顺序分别为 AB、BA，最大输出上限 384 tokens。实际四次完整输出均为 126 tokens，并自然结束。

四个短配对是四条不同金额输入的探索性比较；完整输出只有两对。结果用于判断优化方向，不估计统计显著性、p95、开放域准确率或真实用户的缓存命中率。历史 170–219 秒数据来自其他运行，**本报告的提速比例只使用本次成对对照**，没有把线程调整、冷启动或机器变化算进缓存收益。

## 计时口径

“首 token”从准备查找缓存之前开始，到 streamer 收到首个生成 token 为止，包含缓存键计算、克隆、新输入计算和首 token 选择。“生成耗时”到 `model.generate()` 返回为止，包含完整自回归生成。

两项均不包含预先 tokenize、最终文本解码、Adapter 解析、规划和 Runtime；它们不是当前 CLI 的用户端到端响应时间。CLI 仍需等待完整结构化输出与执行结果，首 token 变快不会自动让 CLI 提前显示最终答案。正确性复核另耗时约 1.31–1.35 秒，但其中包含三个 Runtime 场景，不能直接作为单次请求额外开销相加。

权重加载前的库导入为 3.88 秒，tokenizer 加载 0.36 秒，模型加载函数返回 0.15 秒，短预热 1.32 秒。模型文件已有本地缓存，文件页及映射状态影响这些数值；它们不代表冷盘加载、首次下载或换机器后的启动成本，也没有计入两组生成计时。

## 实测结果

### 完整意图输出

| 请求 | 无前缀复用：首 token | 缓存命中：首 token | 无前缀复用：完整生成 | 缓存命中：完整生成 | 完整生成耗时下降 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 消费后至少保留 15 元 | 41.90 s | 1.72 s | 80.16 s | 35.85 s | 55.3% |
| 消费后至少保留 20 元 | 37.83 s | 1.70 s | 76.36 s | 36.19 s | 52.6% |

两组每次均输出 126 tokens，排除了“输出变短造成加速”这一解释。首个 forward 的实际输入长度由 **1,844 降为 63 tokens**，证明命中路径跳过了公共前缀计算。

缓存命中后，后续 125 个生成 forward 分别耗时 33.90 / 34.26 秒，约占生成总耗时的 **94.6%**；每步约 0.271 / 0.274 秒。无前缀复用组对应约 0.304 / 0.306 秒。后续 token 本来就有请求内 KV，本实验不把这段较小的吞吐差归因为前缀缓存的稳定收益；主要可解释收益是首个 forward 大幅缩短。

### 固定 16-token 短配对

| 保留金额 / 测试顺序 | 无前缀复用生成 | 命中生成 | 无前缀复用首 token | 命中首 token | 生成耗时下降 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 15 / AB | 58.047 s | 5.965 s | 52.086 s | 1.704 s | 89.7% |
| 20 / BA | 51.069 s | 7.739 s | 46.729 s | 1.726 s | 84.8% |
| 50 / AB | 48.180 s | 7.091 s | 43.944 s | 1.720 s | 85.3% |
| 16 / BA | 58.250 s | 5.946 s | 51.824 s | 1.711 s | 89.8% |
| 各组中位数 | **54.558 s** | **6.528 s** | **49.277 s** | **1.716 s** | — |

生成耗时范围分别为 48.18–58.25 秒、5.95–7.74 秒；四对耗时下降比例的中位数为 **87.5%**。短输出更突出前缀计算成本，不能用它的约 85%–90% 收益替代完整输出约 53%–55% 的结果。短输出是截断性能样本，未作为完整意图或业务正确性的证据。

## 首次成本与内存

实际缓存构建为 **48.874 秒**；首次查键、构建和克隆合计 **48.953 秒**。初始化返回的克隆随后丢弃，正式命中样本各自重新复制，不把可变缓存直接共享给后续请求。

首个缓存未命中的完整请求没有一体化计时。按实测组件相加，`纯构建成本 + 命中耗时` 估算为 15 元请求 **84.73 秒**、20 元请求 **85.06 秒**，均略慢于各自无前缀复用的 80.16 / 76.36 秒。这是估算，不能声称首请求已实测提速。

设无前缀复用每请求耗时为 B，命中为 H，构建成本为 C。同一前缀连续可复用时，累计时间近似为 `N×B` 与 `C+N×H`。以本次完整输出的两对数值计算，均从 **第 2 个请求起累计节省时间**；这是固定命中条件下的摊销估计。频繁切换能力目录或教学包会降低收益，真实命中率尚未测量。

| 内存项目 | 实测 / 计算 |
| --- | ---: |
| 单份公共前缀 K/V tensor | 204,259,328 bytes，约 **194.8 MiB** |
| 保留模板 + 单请求克隆的前缀部分 | 约 **389.6 MiB** |
| 本次进程累计峰值 RSS | 约 **4.56 GiB** |

389.6 MiB 不含后缀/生成 token 的 KV、模型权重、临时 tensor、Python 对象及分配器余量。两组运行时都保留了用于实验的缓存模板；命中组的 RSS 采样点还持有请求克隆，因此不能用组间 RSS 相减推算实际部署净增内存。这里直接报告逻辑 KV 大小和进程观测值。

## 正确性与失效验证

六个配对的输出 token **全部精确相同**。四次完整输出经过现有生产解析器，原样解析出的金额、两项 gates、三个 requested outputs、执行计划及业务结果一致。运行产生的随机草稿 ID 在语义比较时忽略，其余能力和资源 ID 保留。

| 实际模型输出的复核场景 | 15 元请求，两组一致 | 20 元请求，两组一致 |
| --- | --- | --- |
| 默认虚构数据 | 生成 1 份 24 元草稿，预算预计剩 16 元 | 剩 16 元不满足保留 20 元，`GateRejected`，0 草稿 |
| 把现金账户余额全部改为 0 | `GateRejected`，0 草稿 | `GateRejected`，0 草稿 |
| 移除财务读取权限 | `PermissionDenied`，0 草稿 | `PermissionDenied`，0 草稿 |

默认现金 4,200 元，消费后预计 4,176 元。共 **12 个 Runtime 场景**符合预期。现金和权限变化使用本次真实模型输出重放，在新的内存 Gateway 上重新读取状态和执行门禁；它们不是额外生成的 8 条模型样本。模型输出仍有原先已知的一个多余结尾 `}`，四次均由现有解析器进行同样的格式修正，未修改事实、gates 或计划。

缓存不保存预算余额、权限决定、执行结果或历史订单草稿。微型随机 Qwen3 的 **5 项机制测试**验证了：仅计算后缀；输出一致；生成修改不会污染模板的 K/V 内容；精确 token 或身份字段改变产生 miss；LRU 淘汰以及无效输入拒绝。它们验证实现机制，不能替代真实模型精度评估或生产多用户测试。

键包含实际前缀 token IDs，以及模型/tokenizer revision、聊天模板、后端、dtype、目录与教学包哈希等。金额改变位于后缀，可以命中；目录、所选学习包、模板或月份改变，必须重新核对键与前缀。实验仅保留一项，不评估多前缀竞争。

实现时捕获过一次有价值的错误：直接对 `messages[:-1]` 重新套 Qwen3 模板，会在最后一条 assistant 示例里插入额外 `<think>` 文本，与完整 prompt 不同。逐 token 断言在性能采样前拦住了它；最终改为从**实际完整 prompt**中截取公共部分，并保留精确 token 校验。该次中止未计入性能样本，提取方法也只针对本次 Qwen3 模板。

## 下一步建议

1. **先把模型与前缀缓存放进 Agent 的长期存活进程。** 保留版本/内容身份、精确 token 核对、缓存长度上限和隔离；继续在每次执行时核对当前权限与数据。无需增加专门承载跨域业务逻辑的中间 Service。
2. **接着优化剩下约 34 秒的解码。** 在目标 M1/Apple Silicon 上实测 MLX/Metal 与量化；CPU 路径另测合适的量化后端。这些性能尚未由本次实验验证，不能给出承诺数字。模型切换后需重跑同一组事实与门禁验收。
3. **再缩减提示词和结构化输出。** 控制教学示例数量，评估能否减少叙述性 goal 输出；以约束保留率为准，不靠截断 JSON 提速。提示缩短还能改善首次构建与低命中率场景，收益需另测。
4. **最后处理 Registry / 学习包验证缓存。** 先前框架重放的普通路径约 1.08 秒，主要模型路径是几十秒。按不可变版本/哈希缓存验证结果值得做，但优先级低于端侧推理。该框架数值来自前次分析，不是本次新增缓存对照。

可以为用户显示推理与执行阶段进度，改善等待体验；最终动作仍应在完整输出解析和门禁验证之后执行。
